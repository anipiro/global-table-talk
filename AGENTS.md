# Gamige — technical rules
- Start the paint request concurrently with recap writing, and await only recap text before leaving the room — why: painting uses existing notebook/media topics, so waiting for every recap adds unnecessary delay.
- Caller-aborted AI requests return cancellation status 499 at both route and global request boundaries; clients treat 499 as cancellation and never log or retry canceled painting — why: leaving the recap during painting is expected, not a screen-crashing failure.
- Claude models use the gateway's native Messages provider in the shared streaming helper — why: the gateway rejects Claude requests on Chat Completions.
- Shared Ground uses attributed recent speech and join facts through the existing cheap trigger/checker; unknown speakers and sensitive topics are excluded — why: spoken interests must be discoverable without checking every caption with an additional AI call.
- Leaving disconnects this phone's mic, whisper and room subscription while retaining its member identity and historical rows — why: returning must preserve the seat and host ownership without deleting the night's records.
- Recap painting selection and notebook exclusion share the media helpers in `src/components/Media.tsx` — why: both views must agree on which existing media rows represent the night's painting without extra AI calls or subscriptions.
- Guests have no accounts; identity is a member id kept in localStorage per room code, and tables use open guest RLS policies — why: join-by-name was a product requirement.
- All AI work goes through the single server route `src/routes/api/agent.ts` (task-based), with model helpers in `src/lib/ai.server.ts` — why: keeps the gateway key server-side and one place to change prompts.
- Client-side agent entry points live in `src/lib/agent.ts`; speech capture and whisper use the browser's built-in speech APIs — why: no extra providers needed.
- Room data loads and subscribes via `useRoom` in `src/lib/useRoom.ts` (which also owns reconnect: backoff retries, reload on online/wake/tab return to catch up on missed rows); screens never open their own realtime channels for room tables — why: one channel per room avoids leaks, and one place handles drops.
- The photos bucket is private; display via signed URLs — why: workspace blocks public buckets.
- Browser end-to-end regressions live in tests/e2e as Python Playwright unittest cases against the running app — why: the sandbox supplies Python Playwright and Chromium without extra project dependencies.
- Speaker attribution is decided in the database: `insert_line` arbitrates only between lines whose words match (same utterance heard by two phones) and flags near-ties/blends as `ambiguous`; manual fixes go through `reassign_line` / `undo_speaker_correction`, which log to `speaker_corrections` — why: atomic, and real overlapping dialogue must never be deleted.
- Labeled overlapping-speech samples live in `src/lib/speakerSamples.json`, shared by the /test/speakers report and tests/e2e/test_side_by_side.py — why: one source of truth for speaker accuracy.
- While the mic is on, phones share live mic levels over a realtime broadcast channel `voice-<room_id>` (opened/closed in `src/lib/agent.ts`, not a room table, so it is outside `useRoom`); a phone only uploads speech it was loudest for, and arbitration compares raw loudness — why: per-phone voice setups vary too much to compare against, and checking before transcription removes overheard copies at the source.
- The Gemini recorder cuts chunks on voice activity (pause or max length), not fixed intervals — why: lower caption delay and no words split across chunks.
- Each phone scores attribution confidence per utterance (level vs the owner's learned voice, share of speech it was loudest for); `insert_line` saves low-confidence lines with no speaker ("Unknown speaker") and `heard_by` = capturing phone. What a phone learns from its owner's lines and from speaker corrections is kept per member in that browser's localStorage — why: loudness levels are specific to the phone that measured them.
- The scripted demo scene lives in `src/lib/demoScript.ts`, shared by the Demo room seed and "Replay demo" on the presenter view (/t/$code/screen, file `t.$code_.screen.tsx` so it is not nested under the join route) — why: one script for both, and a stage fallback without audio or AI.
